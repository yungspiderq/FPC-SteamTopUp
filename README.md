# 💰 SteamTopUp — автопополнение кошелька Steam через DesslyHub

Плагин для [FunPay Cardinal](https://github.com/sidor0912/FunPayCardinal) **v0.1.17+**

**Автор:** yungspider

Покупатель оплатил лот «Пополнение Steam на N ₽» — плагин сам находит его логин Steam
(в полях заказа или вежливо спрашивает в чате), проверяет возможность пополнения,
покупает топ-ап через API [DesslyHub](https://desslyhub.com/ru) и следит за транзакцией до
статуса `success` / `failed`, сообщая покупателю результат.

## Как это работает

```
новый заказ FunPay
      ↓
привязка лота: «Пополнение Steam 500₽» → сумма 500 RUB (или «…5$» → 5 USD)
      ↓
логин Steam: поля заказа → описание → запрос в чате (ждёт wait_data_minutes)
      ↓
проверки: баланс DesslyHub, лимит стоимости, минимальная маржа, ЧС
      ↓
POST check_login (логин существует и пополняем) → конвертация RUB→USD по курсу DesslyHub
POST steam_refill / topup          → transaction_id (reference = номер заказа)
      ↓
опрос статуса                      → pending → success / failed / cancelled
      ↓
success → покупателю «кошелёк $login пополнен на $amount $» · failed → алерт продавцу
```

## Возможности

- 💰 **Полный цикл по API DesslyHub**: проверка логина (`check_login`) → пополнение
  (`steam_refill`) → опрос статуса транзакции/заказа до финала.
- 🌐 **Два поколения API**: legacy (заголовок `apikey`) и v2 (HMAC-подпись `key+secret`,
  единый эндпоинт `/orders`) — режим определяется автоматически, можно переключить вручную.
- 🔗 **Привязка лотов через меню**: фиксированная сумма в USD (`Лот | 5`) или в рублях
  (`Лот | 500 RUB`) — рубли конвертируются по курсу DesslyHub в момент покупки.
- 🔎 **Логин Steam ищет сам**: в полях заказа (названия полей настраиваются), в описании
  и в ссылке на профиль; если не нашёл — просит покупателя в чате и ждёт `wait_data_minutes`,
  подхватывая логин из первого же подходящего сообщения.
- 🧪 **DRY-RUN по умолчанию** — весь сценарий проходит, но покупка **не совершается**:
  можно спокойно настроить привязки и проверить их на реальном заказе, не потратив ни цента.
- 🛡 **Защита денег**: порог баланса DesslyHub, лимит стоимости одной покупки, минимальная
  маржа (доход FunPay в USD против стоимости топ-апа), **ровно одна покупка на заказ** —
  даже при дублях событий и перезапусках.
- ⚠️ **Понятные ошибки по-русски**: `-100` неверный логин, `-2` недостаточно средств и т.д.;
  при `failed`/`cancelled` деньги возвращаются на баланс DesslyHub автоматически.
- 🔁 **Сетевые сбои ретраятся**, бизнес-ошибки — нет (деньги не тратятся дважды).
- 💾 Состояние очереди и транзакций на диске: перезапуск Кардинала не теряет заказы, а
  оборванное пополнение **не повторяется автоматически** (заказ передается вам).
- 📋 Меню `/topup`: баланс, привязки, история операций, статистика, лимиты, тексты сообщений.

## Установка

```bash
cd /home/fpc/FunPayCardinal
wget https://raw.githubusercontent.com/yungspiderq/FPC-SteamTopUp/main/steam_topup.py -O plugins/steam_topup.py
sudo systemctl restart FunPayCardinal@fpc
```

или отправьте файл боту в Telegram → `🔌 Плагины` → `➕ Добавить плагин`.

> ⚠️ Лоты с пополнением **не должны** быть в `configs/auto_delivery.cfg` — иначе Кардинал
> выдаст «товар» сам, вместе с топ-апом.

## Первый запуск (по шагам)

1. `/topup` → **🔑 API-ключ** (и **🔐 Секрет**, если менеджер DesslyHub выдал ключ v2) —
   ключ выдаёт менеджер DesslyHub ([@DesslyHub_Manager](https://t.me/DesslyHub_Manager)).
2. **🧪 Тест подключения** — покажет, какое поколение API отвечает, баланс и курс RUB.
3. **📦 Привязки лотов → ➕ Добавить** в формате `название лота | сумма`:
   ```
   Пополнение Steam 5$ | 5
   Пополнение Steam 500₽ | 500 RUB
   ```
   Название лота должно совпадать с названием из FunPay (или содержать его).
4. Сделайте **тестовый заказ** своего лота, оставив **DRY-RUN включенным**: в Telegram
   придет карточка «что было бы куплено» — логин, сумма в USD, цена.
5. Проверьте, что логин и сумма верные, и только затем **выключайте DRY-RUN** и включайте плагин.

## Использование

Команда **`/topup`** (или `⚙️ Настройки` на странице плагина):

| Кнопка | Действие |
|---|---|
| 🔴 Включить / 🟢 Выключить | Master-switch автопополнения |
| 🧪 DRY-RUN: ВКЛ/ВЫКЛ | Тестовый режим: всё считается, но покупка не совершается |
| 🔑 API-ключ / 🔐 Секрет (v2) | Ввести ключ и секрет DesslyHub (в меню маскируются) |
| 💳 Баланс | Всего / доступно / резерв / овердрафт мерчанта DesslyHub |
| 🧪 Тест подключения | Поколение API + баланс + курс RUB |
| 📊 Статистика выдач | Сколько пополнений прошло и на какую сумму |
| 📦 Привязки лотов | Список, ➕ добавление, 🗑 удаление |
| 🧾 История операций | Последние заказы: статус, логин, сумма, текст ошибки |
| 🔄 Проверить транзакции | Немедленно опросить статусы всех активных транзакций |
| 🛡 Лимиты и защита | Лимит покупки, порог баланса, маржа, валюта FunPay, ожидание данных |
| 💬 Тексты сообщений | Текст запроса логина, текст после успеха, текст при ошибке |
| 🌐 API: auto/legacy/v2 | Переключение поколения API |

### Тексты по умолчанию

Запрос логина (если его нет в заказе):

```
Здравствуйте, $username! Спасибо за покупку 💰
Чтобы пополнить кошелёк Steam, пришлите, пожалуйста, ваш ЛОГИН Steam (тот, под которым
вы входите в Steam - не ссылка и не отображаемое имя).
Пример: coolgamer2010
```

После успешного пополнения:

```
💰 Ваш аккаунт Steam ($login) пополнен на $amount $!
Средства обычно зачисляются в течение 5-30 минут (иногда дольше на стороне Steam).
Спасибо за покупку, $username! Будем рады вашему отзыву ⭐
```

Во всех текстах работают переменные Кардинала (`$username`, `$order_desc`, `$full_date_text`, …),
`$order` (номер заказа), `$login` (логин Steam) и `$amount` (сумма в USD). При ошибке
покупателю по умолчанию **ничего не отправляется** — разбирается продавец (`failed_text` пустой).

## Настройки

`storage/plugins/steam_topup/settings.json` — можно править руками (перечитывается при каждом
обращении) или через меню `/topup`.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `enabled` | `false` | master-switch: обрабатывать ли заказы |
| `dry_run` | `true` | тестовый режим — покупка не совершается |
| `apikey` / `secret` | `""` | ключ DesslyHub и секрет для API v2 (HMAC) |
| `api_mode` | `auto` | `auto` / `legacy` / `v2` — поколение API |
| `base_url` | `https://desslyhub.com` | адрес API |
| `timeout` / `retries` | `20` / `2` | таймаут запроса и число повторов при сетевом сбое |
| `check_login` | `true` | проверять логин через `check_login` перед покупкой |
| `login_field_names` | список | по каким названиям полей заказа искать логин Steam |
| `ask_for_data` | `true` | просить ли логин в чате, если его нет в заказе |
| `ask_data_text` | см. выше | текст запроса логина |
| `wait_data_minutes` | `60` | сколько ждать логин от покупателя |
| `success_text` | см. выше | сообщение покупателю после успеха |
| `failed_text` | `""` | сообщение покупателю при ошибке (пусто = не отправлять) |
| `poll_interval` | `10` | интервал опроса статусов транзакций, секунд |
| `poll_max_minutes` | `90` | после этого транзакция считается «зависшей» → алерт |
| `min_balance_usd` | `5` | порог баланса DesslyHub (ниже — не покупаем + алерт) |
| `max_order_cost_usd` | `100` | лимит стоимости одного пополнения |
| `min_margin_percent` | `0` | минимальная маржа, `0` = проверка выключена |
| `funpay_currency_code` | `5` | код валюты цены заказа (5 RUB, 1 USD, 3 EUR, 18 UAH, 37 KZT) |
| `notify_low_balance` | `true` | уведомление в Telegram о низком балансе |
| `low_balance_repeat_minutes` | `60` | пауза между повторными алертами, минут |
| `mappings` | `{}` | привязки лотов: `{ "название лота": {"amount": 5.0, "currency": "USD"} }` |
| `catalog_cache_minutes` | `720` | время жизни кэша каталога/курсов |

Данные: `storage/plugins/steam_topup/orders.json` (журнал заказов и транзакций),
`storage/plugins/steam_topup/catalog.json` (кэш).

## Важно знать

- **Деньги.** Покупка совершается только при выключенном `dry_run` и только после всех проверок.
  На один заказ — ровно одно пополнение: повторные события FunPay, повторный вызов сценария и
  перезапуск Кардинала не приводят ко второму списанию.
- **Перезапуск во время отправки.** Если бот перезапустился в момент запроса пополнения, заказ
  помечается `error` и приходит алерт: автоматически повторять нельзя — неизвестно, успел ли
  запрос дойти. Проверьте операции DesslyHub и дообработайте заказ вручную.
- **Сумма в рублях.** `500 RUB` конвертируется в USD по курсу DesslyHub в момент покупки —
  цена топ-апа в `$` может немного меняться; маржа считается уже после конвертации.
- **Логин.** Принимаются логины 3–32 символа (латиница, цифры, `_`); ссылка на профиль
  `steamcommunity.com/id/...` тоже распознаётся — из неё берётся vanity-имя. Отображаемое
  имя (ник с пробелами и кириллицей) для пополнения **не подходит** — нужен именно логин.
- **Ошибки.** `-100` неверный логин, `-2` недостаточно средств на балансе DesslyHub,
  `-1` внутренняя ошибка поставщика. Деньги при `failed`/`cancelled` возвращаются на баланс.
- **API-ключ** хранится только на вашем сервере в `settings.json`, в меню показывается
  маскированным, в логи не пишется и никуда не передается, кроме `desslyhub.com`.

## Используемые методы API DesslyHub

| Поколение | Метод | Зачем |
|---|---|---|
| v2 | `GET /api/v1/catalog/steam-refill/check_login/{username}` | проверка логина перед покупкой |
| v2 | `POST /api/v1/orders` (`service_type: steam_refill`) | покупка топ-апа (`reference` = номер заказа) |
| v2 | `GET /api/v1/orders/{order_id}` | опрос статуса до `success`/`failed`/`cancelled` |
| v2 | `GET /api/v1/balance` | баланс мерчанта |
| v2 | `GET /api/v1/currency/exchange_rates/steam/{code}` | курс RUB→USD и маржа |
| legacy | `POST /service/steamtopup/check_login` | проверка логина |
| legacy | `POST /service/steamtopup/topup` | покупка топ-апа |
| legacy | `GET /merchants/transaction/{id}/status` | опрос статуса |
| legacy | `GET /merchants/balance` | баланс мерчанта |
| legacy | `GET /exchange_rate/steam/{code}` | курс для конвертации и маржи |

Документация: [desslyhub.readme.io](https://desslyhub.readme.io/reference/introduction),
коды ошибок: [error-codes](https://desslyhub.readme.io/reference/error-codes).

  повреждение, авторизация legacy+v2 (включая проверку HMAC-подписи), автоопределение поколения
  API, ошибки и ретраи, хранилище, весь Telegram-UI, ввод данных, извлечение логина из полей /
  описания / чата, конвертация RUB→USD, полный цикл выдачи в DRY-RUN и боевом режиме, все
  денежные защиты, идемпотентность, восстановление после перезапуска, поллер и таймауты,
  удаление плагина). Запуск из корня FunPayCardinal:
  ```bash
  cp tests_plugin_steam_topup.py /path/to/FunPayCardinal/
  cd /path/to/FunPayCardinal && pip install -r requirements.txt && python3 tests_plugin_steam_topup.py
  ```
  Тесты создают настройки во временной папке — ваши реальные `storage/plugins/steam_topup/`
  не затрагиваются, запросов в интернет нет.
